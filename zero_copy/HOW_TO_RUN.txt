#  ENGLISH
#####################################################################

STEP 0  What you need
---------------------------------------------------------------------
- JDK 11 or newer (JDK 21 is fine). Check in a terminal:
      java -version
      javac -version
  Both commands must print a version. If "javac" is not found you only
  have the JRE: install a JDK (e.g. Temurin / OpenJDK).
- About 3x the test file size of free disk space (original + download
  + temp file used by the benchmark).

STEP 1  Open a terminal IN the project folder
---------------------------------------------------------------------
The folder that contains Server.java, Client.java, ... and "shared".
- Windows : open the folder in File Explorer, click the address bar,
            type  cmd  and press Enter.
- Linux / macOS : right-click -> "Open in Terminal", or use "cd".
You will need TWO terminals later (one for server, one for client).

STEP 2  Compile
---------------------------------------------------------------------
      javac *.java
No output = success. (If you change any .java file, compile again.)

STEP 3  Run the automated test cases (do this first!)
---------------------------------------------------------------------
      java TestRunner
It starts its own server on port 5055, creates small temporary files,
runs 72 checks and deletes everything afterwards. It takes a few
seconds. Expected last lines:

      ==================================================
       RESULT: 72 passed, 0 failed
      ==================================================

If you see FAIL lines, read the name of the test: it tells you what is
broken (for example "GET range beyond end of file -> ERROR 416").
Exit code is 0 when everything passed, 1 otherwise.
What the tests cover:
  1. Protocol : LIST, INFO, HASH, GET and every error code (400/404/416),
                path traversal (../), overflow, several commands on one
                connection.
  2. Downloads: 7 file sizes (0, 1, 9, 10 bytes, 1000003 bytes, ~5 MB,
                ~8 MB) x io/nio x 1/3/10 workers. Each is compared to
                the original with SHA-256. The tiny and odd sizes test
                the "last worker takes the remainder" rule.
  3. Concurrency: 4 clients (40 connections) at the same time.
  4. Robustness: missing file, client that disconnects mid-transfer,
                downloading over an old output file.

STEP 4  Create a big test file for the experiment
---------------------------------------------------------------------
Try small first (100 MB), use 500-1000 MB for the real experiment:
      java MakeTestFile shared/test.bin 100
      java MakeTestFile shared/test.bin 500
(Works on every OS, no administrator rights. Same name = overwritten.)

STEP 5  Start the server  (Terminal 1)
---------------------------------------------------------------------
      java Server
Expected:
      [server] listening on port 5000, sharing folder: ...\shared
Leave this terminal open. Stop the server with Ctrl+C when finished.
(Other port / folder:  java Server 6000 myfolder)

STEP 6  Try the client  (Terminal 2)
---------------------------------------------------------------------
      java Client localhost 5000 list
          FILE hello.txt 44
          FILE test.bin 524288000

      java Client localhost 5000 info test.bin
          test.bin : 524288000 bytes

      java Client localhost 5000 download test.bin out.bin 10 io
          worker  0  offset=0   length=52428800   ... ms
          ... (10 lines, one per worker)
          Done: 524288000 bytes in 1.234 s = 405.1 MB/s, size+SHA-256 check: OK

      java Client localhost 5000 download test.bin out.bin 10 nio
      java Client localhost 5000 download test.bin out.bin 1 io
      java Client localhost 5000 download test.bin out.bin 1 nio

  Format:  download <filename> <outputFile> [workers] [io|nio]
  "check: OK" means size and SHA-256 equal the original. If it says
  MISMATCH the file is corrupted: do not use that run's numbers.
  The numbers above are only an example, yours will differ.

STEP 7  Run the experiment  (Terminal 2)
---------------------------------------------------------------------
      java Client localhost 5000 benchmark test.bin 3
It runs: one warm-up download (not counted), then io/1, io/10, nio/1,
nio/10, 3 runs each, and prints a table plus averages. With a 500 MB
file allow a few minutes. Copy the table into your report.
Tips for fair results: same file every time, close heavy programs
(browser, games, downloads), keep the laptop plugged in, do not use the
computer while it runs. Repeat the whole benchmark 2-3 times on
different occasions if you have time.

STEP 8  (Optional) Server and client on two computers
---------------------------------------------------------------------
More realistic than localhost (real network).
1. Both computers on the same Wi-Fi / LAN.
2. On the server computer find its IP:  Windows: ipconfig
   Linux/macOS: ip a  or  ifconfig   (look for e.g. 192.168.1.23)
3. Start the server there:  java Server
   Windows asks about the firewall: allow Java on PRIVATE networks.
4. On the client computer, use that IP instead of localhost:
      java Client 192.168.1.23 5000 benchmark test.bin 3
Write in your report that the network was real this time.

STEP 9  Cleaning up
---------------------------------------------------------------------
Delete out.bin and shared/test.bin when you are done (they are big).
benchmark_download.tmp is deleted automatically after the benchmark.

TROUBLESHOOTING
---------------------------------------------------------------------
"javac" is not recognized / not found
    Install a JDK (not only a JRE) and reopen the terminal.
"Error: Could not find or load main class Server"
    You are not in the project folder, or you did not compile yet.
"Error: Connection refused"
    The server is not running, or the port/IP is wrong. Start Server
    first and use the same port in the client.
"Address already in use" (server fails to start)
    Another program (or an old server) uses port 5000. Close the old
    server (Ctrl+C) or use another port:  java Server 6000 shared
    and in the client use 6000.
"Directory not found"
    The server cannot find its folder. Run it from the project folder
    (so that "shared" exists) or give the full path:
    java Server 5000 C:\path\to\shared
"Server replied: ERROR 404 File not found"
    The file is not in the shared folder, or the name is wrong
    (case-sensitive on Linux/macOS, no spaces allowed in names).
Client prints MISMATCH
    The downloaded file differs from the original. Run java TestRunner
    to see if the code is still correct, then repeat the download.
Out of disk space / very slow
    Use a smaller file (100 MB) to test, close other programs.
Thai text in README shows as strange symbols
    Open the .txt with VS Code or Notepad and choose UTF-8.

#  ภาษาไทย

ขั้นที่ 0  สิ่งที่ต้องมี
---------------------------------------------------------------------
- JDK 11 ขึ้นไป (JDK 21 ใช้ได้) ตรวจใน terminal:
      java -version
      javac -version
  ทั้งสองคำสั่งต้องแสดงเลขเวอร์ชัน ถ้าไม่พบ "javac" แปลว่ามีแค่ JRE
  ให้ติดตั้ง JDK (เช่น Temurin / OpenJDK)
- พื้นที่ดิสก์ว่างประมาณ 3 เท่าของไฟล์ทดสอบ (ไฟล์ต้นฉบับ + ไฟล์ที่โหลด
  + ไฟล์ชั่วคราวที่ benchmark ใช้)

ขั้นที่ 1  เปิด terminal "ในโฟลเดอร์โปรเจกต์"
---------------------------------------------------------------------
โฟลเดอร์ที่มี Server.java, Client.java, ... และโฟลเดอร์ "shared"
- Windows : เปิดโฟลเดอร์ใน File Explorer คลิกช่อง address พิมพ์ cmd
            แล้วกด Enter
- Linux / macOS : คลิกขวา -> "Open in Terminal" หรือใช้ cd
ภายหลังต้องใช้ terminal 2 หน้าต่าง (หนึ่งสำหรับ server หนึ่งสำหรับ client)

ขั้นที่ 2  Compile
---------------------------------------------------------------------
      javac *.java
ไม่มีข้อความอะไรออกมา = สำเร็จ (ถ้าแก้ไฟล์ .java ต้อง compile ใหม่)

ขั้นที่ 3  รัน test case อัตโนมัติ (ทำก่อนเลย!)
---------------------------------------------------------------------
      java TestRunner
โปรแกรมจะเปิด server ของตัวเองที่พอร์ต 5055 สร้างไฟล์ชั่วคราวเล็ก ๆ
รันการตรวจ 72 ข้อ แล้วลบทุกอย่างทิ้ง ใช้เวลาไม่กี่วินาที
บรรทัดสุดท้ายที่ควรเห็น:

      ==================================================
       RESULT: 72 passed, 0 failed
      ==================================================

ถ้าเห็นบรรทัด FAIL ให้อ่านชื่อ test เพราะบอกว่าอะไรผิด
(เช่น "GET range beyond end of file -> ERROR 416")
exit code เป็น 0 ถ้าผ่านทั้งหมด และเป็น 1 ถ้ามีข้อที่ไม่ผ่าน
test ครอบคลุม:
  1. Protocol : LIST, INFO, HASH, GET และรหัส error ทุกตัว (400/404/416)
                การโจมตี path traversal (../) ตัวเลขล้น (overflow)
                และการส่งหลายคำสั่งใน connection เดียว
  2. ดาวน์โหลด: ไฟล์ 7 ขนาด (0, 1, 9, 10 byte, 1000003 byte, ~5 MB,
                ~8 MB) x io/nio x 1/3/10 workers เทียบกับไฟล์ต้นฉบับ
                ด้วย SHA-256 ขนาดเล็กและขนาดแปลก ๆ ใช้ทดสอบกฎ
                "worker ตัวสุดท้ายรับส่วนที่เหลือ"
  3. Concurrency: client 4 ตัว (40 connection) พร้อมกัน
  4. ความทนทาน: ไฟล์ที่ไม่มี, client ที่ตัดการเชื่อมต่อกลางทาง,
                ดาวน์โหลดทับไฟล์ปลายทางเดิม

ขั้นที่ 4  สร้างไฟล์ทดสอบขนาดใหญ่สำหรับการทดลอง
---------------------------------------------------------------------
ลองเล็กก่อน (100 MB) แล้วใช้ 500-1000 MB สำหรับการทดลองจริง:
      java MakeTestFile shared/test.bin 100
      java MakeTestFile shared/test.bin 500
(ใช้ได้ทุกระบบปฏิบัติการ ไม่ต้องใช้สิทธิ์ผู้ดูแล ชื่อเดิมจะถูกเขียนทับ)

ขั้นที่ 5  เปิด server  (Terminal 1)
---------------------------------------------------------------------
      java Server
ควรเห็น:
      [server] listening on port 5000, sharing folder: ...\shared
เปิดหน้าต่างนี้ทิ้งไว้ เมื่อเสร็จแล้วกด Ctrl+C เพื่อหยุด server
(เปลี่ยนพอร์ต/โฟลเดอร์:  java Server 6000 myfolder)

ขั้นที่ 6  ลองใช้ client  (Terminal 2)
---------------------------------------------------------------------
      java Client localhost 5000 list
          FILE hello.txt 44
          FILE test.bin 524288000

      java Client localhost 5000 info test.bin
          test.bin : 524288000 bytes

      java Client localhost 5000 download test.bin out.bin 10 io
          worker  0  offset=0   length=52428800   ... ms
          ... (10 บรรทัด หนึ่งบรรทัดต่อ worker)
          Done: 524288000 bytes in 1.234 s = 405.1 MB/s, size+SHA-256 check: OK

      java Client localhost 5000 download test.bin out.bin 10 nio
      java Client localhost 5000 download test.bin out.bin 1 io
      java Client localhost 5000 download test.bin out.bin 1 nio

  รูปแบบ:  download <ชื่อไฟล์> <ไฟล์ปลายทาง> [จำนวน worker] [io|nio]
  "check: OK" แปลว่าขนาดและ SHA-256 ตรงกับไฟล์ต้นฉบับ ถ้าขึ้น
  MISMATCH แปลว่าไฟล์เสีย ห้ามใช้ตัวเลขของรอบนั้น
  ตัวเลขข้างบนเป็นเพียงตัวอย่าง ของคุณจะต่างออกไป

ขั้นที่ 7  ทำการทดลอง  (Terminal 2)
---------------------------------------------------------------------
      java Client localhost 5000 benchmark test.bin 3
โปรแกรมจะดาวน์โหลดอุ่นเครื่อง 1 รอบ (ไม่นับ) แล้วรัน io/1, io/10,
nio/1, nio/10 อย่างละ 3 รอบ แล้วแสดงตารางและค่าเฉลี่ย ไฟล์ 500 MB
ใช้เวลาประมาณไม่กี่นาที คัดลอกตารางไปใส่รายงาน
เคล็ดลับให้ผลยุติธรรม: ใช้ไฟล์เดิมทุกครั้ง ปิดโปรแกรมหนัก ๆ
(เบราว์เซอร์ เกม การดาวน์โหลด) เสียบสายชาร์จโน้ตบุ๊ก และอย่าใช้เครื่อง
ระหว่างที่รัน ถ้ามีเวลาให้รัน benchmark ทั้งชุดซ้ำ 2-3 ครั้ง

ขั้นที่ 8  (ทางเลือก) Server กับ Client คนละเครื่อง
---------------------------------------------------------------------
สมจริงกว่า localhost (เป็นเครือข่ายจริง)
1. ทั้งสองเครื่องอยู่ Wi-Fi / LAN เดียวกัน
2. บนเครื่อง server หา IP:  Windows: ipconfig
   Linux/macOS: ip a หรือ ifconfig  (มองหาเช่น 192.168.1.23)
3. เปิด server บนเครื่องนั้น:  java Server
   Windows จะถามเรื่อง firewall: อนุญาต Java บนเครือข่าย PRIVATE
4. บนเครื่อง client ใช้ IP นั้นแทน localhost:
      java Client 192.168.1.23 5000 benchmark test.bin 3
ให้เขียนในรายงานว่ารอบนี้ใช้เครือข่ายจริง

ขั้นที่ 9  ล้างไฟล์
---------------------------------------------------------------------
ลบ out.bin และ shared/test.bin เมื่อใช้เสร็จ (ไฟล์ใหญ่)
benchmark_download.tmp จะถูกลบอัตโนมัติหลัง benchmark จบ

แก้ปัญหาเบื้องต้น
---------------------------------------------------------------------
"javac" is not recognized / not found
    ติดตั้ง JDK (ไม่ใช่แค่ JRE) แล้วเปิด terminal ใหม่
"Error: Could not find or load main class Server"
    ไม่ได้อยู่ในโฟลเดอร์โปรเจกต์ หรือยังไม่ได้ compile
"Error: Connection refused"
    server ยังไม่เปิด หรือพอร์ต/IP ไม่ถูก ให้เปิด Server ก่อน
    และใช้พอร์ตเดียวกันกับที่ client ใช้
"Address already in use" (server เปิดไม่ขึ้น)
    มีโปรแกรมอื่น (หรือ server ตัวเก่า) ใช้พอร์ต 5000 อยู่ ให้ปิดตัวเก่า
    (Ctrl+C) หรือใช้พอร์ตอื่น:  java Server 6000 shared
    แล้วฝั่ง client ใช้ 6000
"Directory not found"
    server หาโฟลเดอร์ไม่เจอ ให้รันจากโฟลเดอร์โปรเจกต์ (ที่มี "shared")
    หรือใส่ path เต็ม:  java Server 5000 C:\path\to\shared
"Server replied: ERROR 404 File not found"
    ไม่มีไฟล์นี้ในโฟลเดอร์ shared หรือพิมพ์ชื่อผิด
    (Linux/macOS แยกตัวพิมพ์เล็ก-ใหญ่ และชื่อไฟล์ห้ามมีช่องว่าง)
Client ขึ้น MISMATCH
    ไฟล์ที่โหลดไม่ตรงกับต้นฉบับ ให้รัน java TestRunner ดูว่าโค้ดยัง
    ถูกต้องอยู่ไหม แล้วดาวน์โหลดใหม่
ดิสก์เต็ม / ช้ามาก
    ใช้ไฟล์เล็กลง (100 MB) เพื่อทดสอบ และปิดโปรแกรมอื่น
ข้อความภาษาไทยใน README เป็นสัญลักษณ์แปลก ๆ
    เปิดไฟล์ .txt ด้วย VS Code หรือ Notepad แล้วเลือก UTF-8
